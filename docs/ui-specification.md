# 画面仕様書(デザイン作成用)

ゲームサーバー管理ツール「Server Manager」の画面仕様。画面デザイン(モックアップ)作成の基礎資料として、実装済みの全7画面の役割・表示項目・状態を記載する。

## 1. アプリケーション概要

Linux ホスト上のゲームサーバー(systemd ユニット)を、Web ブラウザから起動・停止・状態確認するツール。管理者がユーザー・サーバー・権限を管理し、一般ユーザーは許可されたサーバーだけを操作・閲覧できる。Discord のスラッシュコマンドからも操作できるが、Discord 側に画面はない(Web の画面7で連携設定のみ行う)。

- 表示言語: 日本語
- 利用者: ゲームコミュニティの管理者+メンバー(少人数、社内ツール的な位置づけ)
- 利用デバイス: 主に PC ブラウザ。ダッシュボードはスマホからの操作も想定したい(起動・停止はゲーム中に外出先から行うことがある)

## 2. ユーザー種別と画面アクセス

| 種別 | できること |
|---|---|
| 管理者 | 全サーバーの操作+ユーザー管理・サーバー管理・権限設定・Discord設定(画面5〜7) |
| 一般ユーザー(操作可) | 権限のあるサーバーの状態閲覧+起動・停止 |
| 一般ユーザー(閲覧のみ) | 権限のあるサーバーの状態閲覧のみ(起動・停止ボタンは表示されない) |
| 権限なし | そのサーバーは一覧に一切表示されない(存在自体が見えない) |

認証フローの分岐(画面遷移に影響):

1. ユーザーが1人も存在しない(初回インストール直後)→ 全アクセスが画面1(セットアップ)へ強制遷移
2. 未ログイン → 画面2(ログイン)へ強制遷移
3. 仮パスワード状態のユーザー → 画面3(パスワード変更)へ強制遷移(変更完了まで他画面に行けない)
4. 一般ユーザーが `/admin/*` にアクセス → 拒否

## 3. 共通レイアウト

**ヘッダー(ログイン済みの全画面に表示。画面1・2では非表示)**

| 要素 | 備考 |
|---|---|
| ブランド名「Server Manager」 | クリックでダッシュボードへ |
| ナビリンク「ユーザー管理」「サーバー管理」 | **管理者のみ表示** |
| ナビリンク「パスワード変更」 | 全ユーザー |
| ログイン中のユーザー名 | テキスト表示 |
| ログアウトボタン | |

**共通UIパターン**

- フォームエラー: 画面上部に赤系テキストで表示(入力値は保持される)
- 操作成功: 緑系テキストのメッセージ
- 破壊的操作(削除・仮PW再発行)は実行前に確認ダイアログ(現実装はブラウザ標準 `confirm`。デザインではモーダルに置き換えてよい)

## 4. 画面一覧

| # | 画面 | パス | アクセス |
|---|---|---|---|
| 1 | 初回セットアップ | `/setup` | 未セットアップ時のみ(全員) |
| 2 | ログイン | `/login` | 未ログイン |
| 3 | パスワード変更 | `/change-password` | ログイン済み全員 |
| 4 | ダッシュボード | `/` | ログイン済み全員 |
| 5 | ユーザー管理 | `/admin/users` | 管理者のみ |
| 6 | サーバー管理 | `/admin/servers` | 管理者のみ |
| 7 | サーバー詳細 | `/admin/servers/[id]` | 管理者のみ |

## 5. 各画面の仕様

### 画面1: 初回セットアップ `/setup`

**役割**: インストール直後の最初のアクセスで、最初の管理者アカウントを作成する。作成すると自動ログインしてダッシュボードへ。

**表示項目**
- タイトル「初回セットアップ」
- 説明文: 「このツールはまだ管理者アカウントが登録されていません。最初の管理者アカウントを作成してください。作成すると自動的にログインします。」
- 入力: ユーザー名 / パスワード(8文字以上) / パスワード(確認)
- ボタン: 「管理者アカウントを作成」
- エラー表示(ユーザー名重複、パスワード不一致・短すぎ等)

**デザイン留意点**: ヘッダーなしの単独ページ。ログイン画面と同系統の中央寄せカードレイアウトが自然。

### 画面2: ログイン `/login`

**役割**: ユーザー名+パスワードでログイン。

**表示項目**
- タイトル「ログイン」
- 入力: ユーザー名 / パスワード
- ボタン: 「ログイン」
- エラー表示(認証失敗。「ユーザー名またはパスワードが違います」形式で、どちらが違うかは示さない)

**デザイン留意点**: ヘッダーなし。アプリの入口なのでブランド名「Server Manager」をここに置くとよい。

### 画面3: パスワード変更 `/change-password`

**役割**: パスワードの変更。2つのモードがある:
- **強制モード**(仮パスワードでログインした直後): 変更を完了するまで他画面へ遷移できない
- **任意モード**: ヘッダーからいつでも来られる通常の変更

**表示項目**
- タイトル「パスワード変更」
- 強制モードのみ: 注意バナー「仮パスワードでログインしています。続行するには新しいパスワードを設定してください。」(黄系の警告表示)
- 入力: 現在のパスワード / 新しいパスワード(8文字以上) / 新しいパスワード(確認)
- ボタン: 「パスワードを変更」
- エラー表示(現在PW不一致、確認不一致、短すぎ)

**デザイン留意点**: 強制モードではヘッダーのナビが実質使えない(どこへ行っても戻される)ため、バナーで状況を明確に伝えることが重要。

### 画面4: ダッシュボード `/`

**役割**: ログイン後のホーム。自分が閲覧できるサーバーの状態を一覧し、権限があれば起動・停止する。**このアプリで最も使われる画面**。

**表示項目**
- サーバーカードのグリッド(1サーバー=1カード)。カード内:
  - サーバー名
  - 状態バッジ(下表)
  - 「起動」「停止」ボタン — **操作権限があるユーザーのみ表示**。状態に応じて活性制御
- サーバーが1つも見えない場合の空状態: 「閲覧できるサーバーがありません。管理者に権限の付与を依頼してください。」
- 操作結果メッセージ(起動要求成功/権限エラー等)

**状態バッジ(6種)**

| 状態 | ラベル | 色の意味 | 起動ボタン | 停止ボタン |
|---|---|---|---|---|
| active | 稼働中 | 緑(正常) | 無効 | 有効 |
| inactive | 停止 | グレー(中立) | 有効 | 無効 |
| activating | 起動中… | 黄(遷移中) | 無効 | 有効 |
| deactivating | 停止中… | 黄(遷移中) | 無効 | 無効 |
| failed | 異常終了 | 赤(異常) | 有効 | 無効 |
| unknown | 不明 | グレー | 有効 | 無効 |

**動的挙動(デザインに影響)**
- 5秒ごとに状態を自動更新(タブが前面のときのみ)。リロード操作なしでバッジが変わるため、状態変化が視認しやすいデザインが望ましい
- 起動・停止を押すと通常「起動中…」「停止中…」の遷移状態を経て数秒後に確定状態になる

**デザイン留意点**: スマホでの利用が最も想定される画面。カードは1カラムに折り返し、起動・停止ボタンはタップしやすいサイズに。閲覧のみのユーザーにはボタン領域がない(カードが名前+バッジだけになる)ことも考慮。

### 画面5: ユーザー管理 `/admin/users`

**役割**: 管理者がユーザーの一覧・追加・仮パスワード再発行・削除を行う。

**表示項目**
- ユーザー一覧テーブル: ユーザー名 / 管理者(✓) / 仮PW状態(「仮PW(変更待ち)」または「-」) / 作成日 / 操作(「仮PW再発行」「削除」ボタン)
- ユーザー追加フォーム: ユーザー名 / 「管理者にする」チェックボックス / 「追加」ボタン
  - 補足文: 「作成すると12文字の仮パスワードが発行され、初回ログイン時に本パスワードの設定が強制されます。」
- **仮パスワード表示パネル(最重要要素)**: ユーザー追加・仮PW再発行の直後に一度だけ表示
  - 見出し「仮パスワード発行(この画面でしか表示されません)」
  - 対象ユーザー名+仮パスワード(大きめの等幅フォント、コピーしやすく)
  - 注意文: 「この値は再表示できません。今すぐ本人に伝えてください。初回ログイン時に新しいパスワードの設定が求められます。」

**デザイン留意点**: 仮パスワードパネルは「二度と表示されない」ことが伝わる強い視覚(警告色の枠など)+ワンクリックコピーがあると良い。計画上はモーダル想定(現実装はインラインパネル)。再発行・削除には確認ダイアログ。自分自身の削除・最後の管理者の削除はサーバー側で拒否されるのでエラー表示が出る。

### 画面6: サーバー管理 `/admin/servers`

**役割**: 管理者がサーバー(systemd ユニット)の一覧確認と新規登録を行う。

**表示項目**
- サーバー一覧テーブル: 名前 / ユニット名(例 `game-minecraft.service`、等幅フォント) / 「詳細」リンク(画面7へ)
- 空状態: 「登録済みのサーバーはありません。」
- サーバー追加フォーム:
  - サーバー名(補足: 表示名・Discordコマンドの引数にも使われます)
  - ユニット名: **前後に `game-` と `.service` を固定表示し、中央部分だけ入力する複合入力欄**(例: `minecraft` と入力 → `game-minecraft.service` が登録される)。許可文字は英数字と `. _ @ -`
  - 「追加」ボタン
- エラー表示(名前・ユニット名の重複、使用不可文字)

**デザイン留意点**: ユニット名の複合入力(prefix/suffix アドーン付き input)がこの画面の特徴的コンポーネント。固定部分はグレー背景などで「入力できない」ことを明示。

### 画面7: サーバー詳細 `/admin/servers/[id]`

**役割**: 1つのサーバーについて、基本情報の編集・削除、ユーザーごとの権限設定、Discord 連携設定を行う。3セクション構成の長い画面。

**表示項目**

セクション0(共通): 「← サーバー一覧へ戻る」リンク、タイトル「サーバー詳細: {名前}」、操作結果メッセージ

**セクション1: 基本情報**
- サーバー名(編集可)
- ユニット名(画面6と同じ `game-` / `.service` 固定の複合入力)
- 「更新」ボタン

**セクション2: 権限設定**
- 説明: 「ユーザーごとにこのサーバーへのアクセスレベルを設定します(管理者は常に全権限)。」
- 全ユーザーのテーブル: ユーザー名 / 権限セレクト(**不可・閲覧のみ・操作可** の3択)+「設定」ボタン
  - 管理者の行はセレクトなしで「操作可(固定)」と表示

**セクション3: Discord設定**
- 説明: 「ここで許可した Discord チャンネルから、スラッシュコマンド(/server start など)でこのサーバーを操作できます。チャンネル単位の許可制で、許可のないチャンネルやDMからは操作できません。」
- 折りたたみヘルプ「DiscordサーバーID・チャンネルIDの取得方法」(3ステップの手順)
- 許可チャンネル一覧テーブル: DiscordサーバーID / チャンネルID(いずれも18桁前後の数値、等幅フォント)/ 「削除」ボタン
- 空状態: 「許可されたチャンネルはありません。」
- 追加フォーム: DiscordサーバーID / チャンネルID(数字のみ、placeholder `123456789012345678`)/ 「チャンネルを許可」ボタン

**最下部: 削除**
- 「このサーバーを削除」ボタン(赤系・確認ダイアログ付き。権限設定と Discord 設定も一緒に消える)

**デザイン留意点**: セクションが多いので見出し・区切りの階層を明確に。削除ボタンは他の操作から視覚的に隔離(danger zone)。

## 6. デザイン作成上のその他の重要情報

**トーン**: 運用ツール。装飾より状態の視認性(特にダッシュボードのバッジ色)と誤操作防止を優先。ダークテーマとの親和性が高いジャンル(ゲーマー向け)だが、指定はないので提案ベースでよい。

**色のセマンティクス(全画面で一貫させる)**
- 緑=稼働・成功、赤=異常・危険操作、黄=遷移中・警告(仮PW関連)、グレー=停止・中立

**タイポグラフィ**: ユニット名・Discord ID・仮パスワードなどの機械的な値は等幅フォント。仮パスワードは特に大きく、選択・コピーしやすく。

**画面規模**: 全7画面・SPA的な複雑さはなし。フォーム+テーブル+カードが主要コンポーネント。モーダル(または確認ダイアログ)は「破壊的操作の確認」と「仮パスワード表示」の2用途。

**レスポンシブ優先度**: 画面4(ダッシュボード)>画面2・3(ログイン・PW変更)>管理画面(PC前提でよいが崩れない程度に)。

**実装技術**: Svelte 5(SvelteKit)。スタイルはコンポーネント内 scoped CSS。現状 CSS フレームワーク・デザイントークンは未導入のため、モックアップで定義するトークン(色・余白・角丸)がそのまま実装基準になる。
